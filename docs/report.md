### Мета роботи

Створити структурований серверний API на FastAPI, визначити моделі й контракт операцій, відокремити HTTP-рівень від тимчасового сховища та перевірити поведінку автоматизованими тестами й колекцією клієнтських запитів.

### Індивідуальний варіант

Номер у списку 15. Остача 15 % 4 = 3. Реалізоване поле academic_status у створенні, читанні, частковому оновленні та фільтрації списку.

Для навчальної моделі визначено явний перелік: active - навчається; academic_leave - академічна відпустка; graduated - завершив навчання; expelled - відрахований. Невідомі значення відхиляються з 422.

### Структура реалізації

```text
digital-dean-api/
  app/
    main.py                     # фабрика застосунку та помилки
    api/students.py             # HTTP-операції
    schemas/student.py          # моделі та AcademicStatus
    schemas/error.py            # вихідна схема помилок
    repositories/student_repository.py
  tests/                        # ізоляція стану та тести
  postman/                      # колекція 2.1
  docs/                         # гайд, звіт і OpenAPI
  evidence/                     # результати перевірок
  pyproject.toml
  setup.cmd  start.cmd  test.cmd
```

Шлях даних: HTTP-запит -> FastAPI -> валідація Pydantic -> InMemoryStudentRepository -> StudentRead -> JSON-відповідь. Застосунок створюється фабрикою create_app; кожен його екземпляр має окреме сховище.

## Контракт і валідація

| Метод | Шлях | Успіх | Помилки |
| --- | --- | --- | --- |
| GET | /health | 200 | - |
| POST | /api/v1/students | 201 | 409, 422 |
| GET | /api/v1/students | 200 | 422 |
| GET | /api/v1/students/{student_id} | 200 | 404, 422 |
| PATCH | /api/v1/students/{student_id} | 200 | 404, 409, 422 |

POST повертає заголовок Location. GET списку підтримує необовʼязковий параметр academic_status. Формат помилок 404 і 409: detail із code та message; помилки 422 містять список detail з type і loc. Відкриті /docs та /openapi.json.

### Обмеження полів

full_name має 5-120 символів після вилучення крайніх пробілів. email перевіряється типом EmailStr і є унікальним без урахування регістру. group_code містить одну чи більше великих латинських або українських літер чи цифр, дефіс і рівно дві ASCII-цифри.

```text
^[A-ZА-ЩЬЮЯЄІЇҐ0-9]+-[0-9]{2}$
```

StudentCreate містить лише клієнтські поля. StudentRead додає UUID, згенерований сервером. StudentUpdate дозволяє пропуск полів, але відхиляє {} та явно переданий null. Конфігурація extra="forbid" відхиляє невідомі поля, зокрема is_admin та клієнтський id.

### Ключові фрагменти реалізації

```text
class AcademicStatus(StrEnum):
    ACTIVE = "active"
    ACADEMIC_LEAVE = "academic_leave"
    GRADUATED = "graduated"
    EXPELLED = "expelled"

changes = payload.model_dump(exclude_unset=True)
if "email" in changes:
    self._check_email(str(changes["email"]), exclude_id=student_id)
updated = StudentRead.model_validate({**current.model_dump(), **changes})
```

При PATCH поточний запис виключається з пошуку дубля email. Злитий запис проходить повторну валідацію до запису у сховище. Перевірка унікальності та зміна виконуються під одним RLock; невдала операція не змінює інші поля.

## Результати перевірок

### Автоматизовані тести

Фактичний запуск на Python 3.12.14 завершився результатом 57 passed, 1 warning. Повний вивід збережено в evidence/pytest.txt. Попередження бібліотеки Starlette щодо httpx не вплинуло на результат перевірок.

Покрито health, створення з серверним UUID, список, отримання, відсутній та некоректний UUID, часткові зміни кожного поля, заборону порожнього PATCH, null і невідомих полів, некоректний JSON, межі full_name, алфавіт group_code, дублікати email на POST і PATCH, атомарність конфліктної зміни та OpenAPI.

Спеціальні перевірки варіанта: створення з кожним із чотирьох прийнятних станів; фільтрування різних станів; зміна статусу та її видимість у фільтрі; порожній результат; відхилення невідомих значень у тілі й параметрі запиту.

### Колекція Postman

Колекцію формату 2.1 виконано через Newman 6.2.3 проти справжнього локального HTTP-сервера Uvicorn. Результат: 20 запитів, 42 твердження, 0 провалів. Вивід: evidence/newman.txt; машинний звіт: evidence/newman-results.json.

Перші десять запитів відповідають обовʼязковій послідовності завдання. Додатково перевірено порожній PATCH, невідомий статус, оновлення статусу, фільтр нового стану, невідомий фільтр, заборону зміни id, null, конфлікт email під час PATCH та незмінність запису після відхилення.

### Реальний запуск і пакування

Операції /health, /docs та /openapi.json перевірено через HTTP: усі повернули 200. Python-пакет успішно зібрано у wheel та встановлено в окремий каталог. Точні версії перевіреного середовища наведено у requirements-tested.txt.

### Ізоляція і дані

Fixture створює окремий застосунок і очищує репозиторій до та після кожного сценарію. Тести не потребують окремого мережевого процесу. Для демонстрації та колекції використано вигадані записи з email у домені example.com.
