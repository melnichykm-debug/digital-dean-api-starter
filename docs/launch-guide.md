# Як запустити Цифровий деканат

Практична робота 1. Номер у списку 15, варіант 3 - academic_status. У комплекті готовий FastAPI-проєкт, тести, колекція Postman, звіт і локальна історія Git.

### 1 Підготуйте компʼютер

Потрібен Python 3.12 або новіший із pip. Для першого встановлення залежностей потрібен інтернет. Postman і Git потрібні для перевірки колекції та публікації роботи.

Повністю розпакуйте ZIP. Відкрийте папку digital-dean-api, де лежать pyproject.toml і setup.cmd. Не запускайте файли безпосередньо з архіву.

### 2 Запустіть у Windows

Двічі натисніть setup.cmd і дочекайтеся повідомлення Setup complete. Потім відкрийте start.cmd. Вікно сервера залиште відкритим. setup.cmd створює окреме середовище .venv і встановлює залежності; повторний запуск setup.cmd дозволений.

Відкрийте http://127.0.0.1:8000/docs. Для перевірки готовності відкрийте http://127.0.0.1:8000/health - очікується {"status":"ok"}.

### 3 Ті самі дії через PowerShell

Відкрийте термінал саме в папці digital-dean-api та виконайте команди по одній. Активація середовища не потрібна.

```text
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Версія в першій команді має бути не нижче 3.12. Для зупинки натисніть Ctrl+C у вікні сервера. Під час наступного запуску достатньо start.cmd.

## Перевірка API у браузері

На сторінці /docs розгорніть потрібну операцію, натисніть Try it out, заповніть дані та натисніть Execute. Для повторного POST змінюйте email або перезапустіть сервер.

### Створіть студента

Операція POST /api/v1/students. Вставте цей JSON. Поле id не передавайте - його генерує сервер.

```text
{
  "full_name": "Олена Коваль",
  "email": "olena.koval@example.com",
  "group_code": "КН-31",
  "academic_status": "active"
}
```

Очікується 201 Created. Скопіюйте id із відповіді. У GET /api/v1/students список міститиме створений запис. У GET /api/v1/students/{student_id} вставте скопійований UUID - очікується 200 і повний запис.

### Виконайте часткове оновлення

Операція PATCH /api/v1/students/{student_id}. Передайте скопійований UUID та лише поле, яке хочете змінити.

```text
{"group_code": "КН-32"}
```

Очікується 200. Зміниться group_code; id, full_name, email та academic_status збережуться. Порожній обʼєкт {}, явний null, поле is_admin або спроба змінити id дають 422.

### Перевірте варіант 3

Навчальні стани: active - навчається; academic_leave - академічна відпустка; graduated - завершив навчання; expelled - відрахований. Значення чутливі до регістру. Це явний перелік для цієї роботи.

```text
GET /api/v1/students?academic_status=active
PATCH /api/v1/students/{student_id}
{"academic_status": "academic_leave"}
```

Після PATCH запис зʼявиться у фільтрі academic_leave і зникне з active. Невідоме значення стану дає 422; коректний UUID без запису - 404; повторний email без урахування регістру - 409.

## Автоматизовані тести та Postman

### Перевірка pytest

Відкрийте test.cmd або другий термінал у папці проєкту. Запущений сервер для pytest не потрібен.

```text
.\.venv\Scripts\python.exe -m pytest
```

Перевірений результат комплекту: 57 passed. Кожен тест має окремий очищений репозиторій. Перевіряються створення, читання, PATCH, валідація, конфлікти email, UUID, статуси, фільтрація та OpenAPI.

У перевіреній комбінації бібліотек є одне попередження Starlette про майбутній перехід із httpx на httpx2. Воно не є провалом тесту. Точні версії збережено у requirements-tested.txt.

### Перевірка Postman

1. Запустіть start.cmd. У Postman натисніть Import і виберіть файл postman/digital-dean-practice-01.postman_collection.json.

2. У змінних колекції перевірте base_url = http://127.0.0.1:8000. Якщо змінено порт, виправте base_url. Приберіть однойменну змінну з активного Environment або вкажіть там ту саму адресу.

3. Запустіть усю колекцію через Run collection: один прохід, усі 20 запитів у початковому порядку. Другий запит зберігає student_id, який використовують наступні.

4. Очікується 20 виконаних запитів, 42 успішні твердження та 0 провалів. Колекція генерує унікальні email для кожного повного проходу, тому її можна запускати повторно без очищення сервера.

### Запуск тієї самої колекції через Newman

Це необовʼязкова альтернатива інтерфейсу Postman. Потрібні Node.js та npm. Саме Newman 6.2.3 використано для перевірки доданої колекції на реальному HTTP-сервері.

```text
npx --yes newman@6.2.3 run postman/digital-dean-practice-01.postman_collection.json
```

Фактичні результати дивіться в evidence/pytest.txt, evidence/newman.txt, evidence/newman-results.json і evidence/summary.json. Збережений контракт міститься в docs/openapi.json.

## Як опублікувати роботу у своєму форку

Код і локальна історія готові. Для виконання вимоги GitHub залишилося створити власний форк і опублікувати гілку та тег. Це потребує входу у ваш обліковий запис. Публікація з цього комплекту автоматично не виконувалася.

### 1 Створіть повʼязаний форк

Відкрийте github.com/serhii-ch-eu/digital-dean-api-starter та натисніть Fork у власний обліковий запис. Збережіть імʼя digital-dean-api-starter.

### 2 Відновіть готову історію

У терміналі перейдіть у кореневу папку розпакованого комплекту, де лежить practice-01.bundle. Це інша папка, ніж вкладена папка з кодом. Виконайте:

```text
git clone -b practice-01 practice-01.bundle digital-dean-api-git
cd digital-dean-api-git
```

Git bundle містить історію викладацького шаблону, змістові фіксації розвʼязку, гілку practice-01 та фінальний тег practice-01. Не виконуйте git init: історія вже існує.

### 3 Налаштуйте адреси та опублікуйте

У першій команді замініть LOGIN на власний логін GitHub. origin має вказувати на ваш форк. upstream має вказувати на репозиторій викладача.

```text
git remote set-url origin https://github.com/LOGIN/digital-dean-api-starter.git
git remote add upstream https://github.com/serhii-ch-eu/digital-dean-api-starter.git
git remote -v
git branch --show-current
git log --oneline --decorate -n 10
git push -u origin practice-01
git push origin tag practice-01
git ls-remote --tags origin practice-01
```

Якщо GitHub запросить вхід, авторизуйтеся своїм звичним способом. Тег уже створений у bundle, тому повторна команда git tag practice-01 не потрібна.

### 4 Доповніть звіт

У docs/report.md заповніть ПІБ, групу, викладача та адресу форку. Додайте посилання на гілку, вивід git remote -v і git ls-remote --tags origin practice-01 після публікації. В архіві є PDF звіту з фактичними локальними результатами.

## Типові проблеми та склад комплекту

### Python або py не знайдено

Установіть Python 3.12 або новіший із pip та Python Launcher, після чого відкрийте новий термінал. Якщо працює команда python --version, але немає py, у перших двох командах ручного запуску замініть py -3 на python.

### No module named fastapi або помилка pip

Виконайте setup.cmd або команду встановлення з першої сторінки. Перевірте інтернет і що поточна папка містить pyproject.toml. Для запуску використовуйте саме .venv/Scripts/python.exe, а не інший Python.

### Порт 8000 зайнято або браузер не підʼєднується

Зупиніть попередній сервер через Ctrl+C. Або запустіть на 8001 і відкрийте http://127.0.0.1:8001/docs; у Postman також змініть base_url.

```text
.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8001 --reload
```

### Дані зникли після перезапуску

Це очікувана поведінка сховища в памʼяті. Перезавантаження коду з --reload також очищує дані. Створіть записи знову або повторно запустіть усю колекцію Postman. Використовуйте один процес сервера.

### Файли комплекту

digital-dean-api/app - моделі, маршрути та репозиторій; tests - 57 перевірок; postman - колекція з 20 запитами; docs - текст гайду, звіт і OpenAPI; evidence - фактичні результати; setup.cmd, start.cmd, test.cmd - команди для Windows; practice-01.bundle - історія Git.

requirements-tested.txt фіксує перевірені версії пакетів у Windows на Python 3.12. За потреби їх можна використати як обмеження версій:

```text
.\.venv\Scripts\python.exe -m pip install -e ".[dev]" -c requirements-tested.txt
```

### Межі навчального застосунку

Дані зберігаються лише в памʼяті одного процесу. Бази даних, авторизації, TLS та видалення немає. Для демонстрації використовуйте вигадані записи. Сервіс за замовчуванням доступний лише на 127.0.0.1.
